# QGC mission control implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Start and recover each selected onboard mission through native QGC, keep the browser responsible for simulation setup and observation, and correct ordinary competition landing under the strict precision profile.

**Architecture:** A shared companion command owner validates QGC actions and uses the existing immutable operator-admission protocol. DroneKit and pymavlink adapters preserve the actual FC-routed command path; existing mission hosts retain execution. A guarded ordinary-landing transaction temporarily changes only PLND_ENABLED and verifies restoration before releasing a later phase.

**Tech Stack:** Python 3.12, pymavlink 2.4.49, DroneKit 2.9.2, ArduPilot SITL, ROS 2 Jazzy, Gazebo Harmonic, native arm64 Colima, native macOS QGC 5.0.8, browser JavaScript/noVNC.

**Spec:** [Approved local simulation console specification](../specs/2026-10-08-local-simulation-console-spec.md).

**Status:** Written after specification approval on 2026-10-09; awaiting plan review. No runtime changes or new flight acceptance are claimed. The completed browser-console plan is preserved in Git at `e546d3c:docs/superpowers/plans/2026-10-08-local-simulation-console.md`.

## Global constraints

- Work in `/Users/williserdman/Documents/projects/drone_sim-console`, branch `feature/local-simulation-console`; preserve PR #3 ancestry, the original checkout, and existing evidence.
- One selected complete preset per run. QGC Start invokes the existing automatic sequence or configured plan, not legacy phase-by-phase commands or a QGC Plan upload.
- Keep `launch_mode=operator`, immutable run/configuration/request/admission identity, the native 50 ms epoch, Comp2026's first-command deadline, and configured execution-release behavior. Unattended runs and descriptor-absent historical configurations retain their meaning and bytes.
- Protocol `qgc_actions_v1`: COMMAND_LONG over MAVLink 2; commands 31020/31021; target 1/191; param1 an integer in 1..16,777,215; params2–7 zero. QGC 255/190, companion 1/191, FC 1/1 are distinct identities. Verify the installed QGC sender before accepting this profile.
- One connection reader per transport. QGC → host byte relay → SITL SERIAL1 → FC routing → companion SERIAL0; the host never synthesizes a flight request or ACK.
- Browser focus, timers, and viewer heartbeats cannot gate QGC flight actions. Required vehicle, native-clock, calibration, and producer checks remain. Stop Simulation finalizes infrastructure and does not establish landing.
- Ordinary landing temporarily sets `PLND_ENABLED=0`, then verifies `PLND_ENABLED=1` after touchdown. Keep `PLND_STRICT=2` and every other precision setting unchanged. No fake targets, force arming, or relaxed artifact/scoring rules.
- Fresh unexpected FC mode/arm transitions revoke onboard intent. Finalization and authority loss stop future aircraft/payload writes at enqueue. QGC observations never fabricate RC takeover evidence.
- Read affected module guides before editing. Update those guides, architecture, runbook, handoff, and `docs/LEDGER.md` with the corresponding change and its actual verification scope.

## Review focus

1. Old action files, missing/corrupt ledgers, and repeat preparation must never reuse a token or start a different run: Task 1 allocation tests and Task 7 native QGC repeat.
2. Lost ACKs, concurrent Start, and a process crash after durable reservation must not create another worker, epoch, or arm: Task 2 retry/restart tests and Task 3 transport integration.
3. A QGC LAND/Pause arriving between operation selection and packet enqueue must stop later output; Operator Wait must still work: Task 4 writer-race and host tests.
4. An old matching parameter cache, failed restoration, or Abort during disable must not release FM2/FM3 with the wrong profile: Task 5 transaction and recovery tests.
5. Closing the browser must leave QGC usable, while Stop during pending admission/recovery must win: Task 6 browser/endpoint tests, Task 2 finalization tests, and Task 7 actual closed-browser flight.
